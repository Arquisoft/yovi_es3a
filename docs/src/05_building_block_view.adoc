[[section-building-block-view]]
== Building Block View

La vista de bloques muestra la descomposición estática del sistema y sus dependencias principales.

=== Whitebox Overall System

_**Overview Diagram**_

image::building_blocks_overview.png[Overview Diagram]

Motivation::

El sistema se descompone en cuatro bloques principales siguiendo una arquitectura de microservicios desacoplados:

- `webapp`: interfaz de usuario
- `users`: microservicio REST
- `gamey`: motor de juego en Rust
- Stack de monitorización

Esta separación permite bajo acoplamiento, escalabilidad independiente y separación clara entre lógica de dominio y presentación.


Contained Building Blocks::

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| webapp | Interfaz de usuario desarrollada en React con TypeScript.
| users | Microservicio Node.js/Express para gestión de usuarios.
| gamey | Motor de juego que implementa la lógica del dominio.
| Monitoring Stack | Monitorización con Prometheus y Grafana.
|===


Important Interfaces::

- HTTP REST entre `webapp` y `users`
- HTTP REST entre cliente y `gamey`
- Endpoint `/metrics` para Prometheus
- Comunicación interna mediante red Docker


==== webapp

_Purpose/Responsibility_

Gestiona la interacción con el usuario, autenticación (login/registro) y realiza llamadas HTTP al backend.

_Interface(s)_

- POST `/createuser` - Crear nuevo usuario
- POST `/login` - Autenticar usuario
- GET `/metrics` - Métricas de Prometheus
- Solicitudes HTTP al motor `gamey`

_Directory/File Location_

`webapp/`


==== users

_Purpose/Responsibility_

Servicio REST que gestiona el registro, autenticación y almacenamiento de usuarios. Expone métricas del sistema.

_Interface(s)_

- POST `/` - Crear usuario
- GET `/` - Listar usuarios
- GET `/username/:username` - Obtener usuario por nombre
- POST `/auth` - Verificar contraseña (autenticación)
- GET `/:id` - Obtener usuario por ID
- DELETE `/:id` - Eliminar usuario
- GET `/metrics` - Métricas de Prometheus

_Directory/File Location_

`users/`


==== gamey

_Purpose/Responsibility_

Implementa la lógica del juego de Y, incluyendo algoritmos de inteligencia artificial para oponentes computacionales.

_Interface(s)_

- API HTTP (modo servidor)
- CLI (línea de comandos)
- Biblioteca interna Rust

_Directory/File Location_

`gamey/`


==== Monitoring Stack

_Purpose/Responsibility_

Recolecta y visualiza métricas del sistema mediante Prometheus y Grafana.

_Interface(s)_

- Scraping de `/metrics` desde `users` y `gamey`

_Location_

`docker-compose.yml`


=== Level 2

==== White Box webapp

image::webapp_internal_structure.png[Webapp Internal Structure]

Motivation::

Se detalla la estructura interna por ser el punto de entrada del sistema y responsable de la autenticación de usuarios.

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| main.tsx | Punto de entrada de la aplicación React.
| App.tsx | Componente raíz que gestiona el estado de autenticación.
| RegisterForm.tsx | Componente de registro de nuevos usuarios.

|===


==== White Box gamey

image::gamey_internal_structure.png[Gamey Internal Structure]

Motivation::

Contiene la lógica más compleja del sistema, implementada en Rust para máximo rendimiento.

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| main.rs | Selección de modo de ejecución (CLI, servidor HTTP o humano vs IA).
| lib.rs | Organización modular y re-exportación de tipos públicos.
| core/mod.rs | Tipos fundamentales del juego.
| core/game.rs | Lógica del juego y máquina de estados.
| core/coord.rs | Sistema de coordenadas baricéntricas.
| core/movement.rs | Representación de movimientos.
| core/player.rs | Definición de jugadores.
| core/action.rs | Acciones especiales del juego.
| bot | Estrategias de inteligencia artificial.
| bot_server | Servidor HTTP que expone la API del bot.
| cli | Interfaz de línea de comandos.
| notation | Formato de notación de juego (YEN).
|===


=== Level 3

==== White Box core/game.rs

Motivation::

Contiene el núcleo algorítmico del sistema, implementando la lógica central del juego de Y.

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| GameY | Estructura principal que encapsula el estado completo de una partida.
| board_size | Tamaño del tablero triangular.
| board_map | HashMap que mapea coordenadas a jugadores (representación del tablero).
| history | Vector de movimientos realizados durante la partida.
| sets | Estructura Union-Find para detección eficiente de conectividad entre piezas.
| available_cells | Lista de celdas disponibles donde se pueden colocar piezas.
| GameStatus | Enum que representa si el juego está en progreso o finalizado.
| Cell | Enum que representa el estado de una celda (vacía u ocupada).
|===

==== White Box core/coord.rs

Motivation::

Define el sistema de coordenadas utilizado en el tablero triangular.

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| Coordinates | Estructura de coordenadas baricéntricas (x, y, z) para ubicar celdas en el tablero triangular.
|===

==== White Box core/movement.rs

Motivation::

Define los tipos de movimientos que pueden realizarse en el juego.

[cols="1,2", options="header"]
|===
| **Name** | **Responsibility**
| Movement | Enum que representa un movimiento: colocación de pieza o acción especial.
| GameAction | Enum con acciones especiales como intercambio (swap) o abandono (resign).
|===
